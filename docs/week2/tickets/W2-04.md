# W2-04: Master CV import

**Points:** 4 · **Wave:** 2 · **Risk:** Med · **Depends on:** W2-03
**Read first:** contract §2, §3.1, §3.2, §8.1, §10 (W2-04); [[review-contract]]. Plan: [[implementation-plan]]. Skills by step: [[skills-map]].

## Summary
Your LinkedIn export becomes `career/master.md` (every bullet has a stable id) and `career/contact.md`, proposed through the review queue as one `career_master_import` item. After you approve it, both files are yours: you edit them in Obsidian and the app never overwrites them.

## Steps
1. **Recall.** `/claude-mem:mem-search <ticket topic>`; before opening a long file, `/claude-mem:smart-explore` it. Keep claude-mem **off** in any session that opens a real CV, contact file, posting or the vault (see [[Workflow]]).
2. **Where the data comes from (plan R5).** LinkedIn's own data export, saved as CSV files in `dataDir/career/import/`. The LinkedIn skills repository (`sergebulaev/linkedin-skills`) is for writing posts and doesn't export profile data, so it is not the source here. The app never reads LinkedIn credentials; `.env` is for API keys only.
3. **Learn the library.** `/claude-mem:make-plan`, phase 0 only: read the `csv-parse` docs (sync API, `columns: true`, quoted line breaks). Then read the header rows of your real export (plan §8 item 2). If it isn't there yet, build against a synthetic fixture that uses the documented headers and say so in the PR.
4. `server/src/career/master.ts`: parse and serialise the strict grammar of contract §3.1; id rules (entry id, bullet id from a hash of the text, ≤ 64 characters, unique); `validateMaster(text)`.
5. `server/src/career/linkedin.ts`: map `Profile.csv`, `Positions.csv`, `Education.csv`, `Skills.csv`, `Languages.csv`, `Certifications.csv` **by header name** (case-insensitive) into entries, bullets, skills and languages. Split a position description into bullets on line breaks and bullet characters. Tolerate missing files; require `Positions.csv` or `Profile.csv`. Report unknown headers instead of guessing. Name from `Profile.csv` goes to `contact.md`; email, phone, address and URL stay empty for you to fill in.
6. `POST /api/career/master/import` reads **only** `dataDir/career/import/` (no client-supplied path), caps each file at 5 MB, returns `201 { approval_id }` or `409 master_exists` / `400 import_empty`. One pending import at a time: a new one replaces the pending payload.
7. Approval type `career_master_import`: a branch in `approvals/apply.ts` that writes both files inside the approval's transaction, hash-checked against `*_hash_before`, `vault_notes.last_written_by='user'`, vault git commit (pattern: the `vault_conflict` branch). Add the type to the exemption in `approvals/expire.ts`.
8. Web: add the case to the `Approval` union in `web/src/api.ts` and a branch in `ApprovalCard.vue` (counts and a `<pre>` preview of the master text, as text). Add the row to `docs/week1/review-contract.md`.
9. **Check.** `pnpm verify` (judge by exit code) → `/simplify` → `/ponytail:ponytail-review` on the diff → `/code-review medium`, and **`/security-review`** (it reads files and writes the vault).
10. **Close.** Tick the acceptance list; `save_memory` (cause → fix for any mistake) and a `CLAUDE.md` Lesson in the same PR if one happened; `/claude-mem:babysit` the PR; `/claude-mem:handoff` if you pause. After reporting ready, push nothing (rule 8).
